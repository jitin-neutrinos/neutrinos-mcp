# Guard-Out-Routing

<https://documentation.neutrinos.com/articles/#!client-services-designer-9/guard-out-routing>

Guard-Out-Routing uses the canDeactivate method to return a value (Boolean) to determine if the current user is allowed to deactivate a route. Which means whether an user is allowed to leave a page is determined by this method.

The Guard-Out-Routing node can be bonded with script node where you can define the routing out logic.

**How to Use**

1. On the Client services editor, Open an existing Can-Deactivate service from the service list or click the** plus icon **to add a new Can-Deactivate Service.
2. Go to the Service > Drag and Drop the Guard-Out-Routing node to the canvas.
3. Drag and drop other node to define the routing logic in the service flow.

**Node Properties**

**Name: **Unique name of the node which will be displayed on the canvas. The default value of the name is Guard-Out-Routing.

**Input Variables: **A list of read-only **bh.** variables in key value pairs generated by default by the node.

| **Key Element** | **Description** | **Value** |
| --- | --- | --- |
| bh.navigationRoute | Each page component in your app is associated with a route. This variable contains the information of the route associated with a page component loaded at a particular time | Value: ActivatedRouteSnapshot |
| bh.navigationRouteState | Contains the information of the state of router at a moment in time | Value: RouterStateSnapshot |

**Local Variables:** Use this field to initialize the local variables for the flow. Local variables are private to the flow and cannot be accessed outside the flow.
