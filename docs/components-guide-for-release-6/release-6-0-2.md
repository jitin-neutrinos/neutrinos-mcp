## Creating a Plugin

Starting from version 6.0.2, you can create a plugin of your own and import it to Neutrinos Studio. A plugin can be a palette component, a Modelr node, an Angular package, or a combination of them.

This topic guides you through the steps required to create a component. It includes recommendations, best practices, and information for common situations.

### Plugins

Plugins are one of the most important aspects of low-code platforms, which enable the reusability of code. As a result, developers can build high-quality app components and share them with others, boosting application development time and code fragmentation.

A plugin is a reusable object that speeds up application creation and delivery. It can be either an application or a module that provides additional features. After you create a plugin, there are three possible outcomes:

- It can modularize your code to be reused within your application
- It can be reused in more than one applications
- It can be published to Neutrinos MarketPlace where it will serve several apps and developers

**Plugin Types**

You can create and upload the following types of Plugins to Neutrinos Store:

- Studio component
- Angular package
- Modelr node

You can also create a combination of a component, Modelr node, and Angular package as a plugin.

### Recommendations and Best Practices

To successfully create a plugin, you should:

1. Decide its purpose
2. Define its presentation by giving it the right names and assigning the required metadata
3. Follow a set of best practices that enhance the experience of reuse and maintenance
4. Test the component to make sure that you cover non-functional requirements, such as performance, security, and scalability

Once you are through with all the steps, you can submit the plugin to Neutrinos to publish it on Neutrinos Store. Make sure you use Neutrinos Studio version 6.0.2 or higher to create a plugin.
