# Resolve Node

<https://documentation.neutrinos.com/articles/#!client-services-designer-8/resolver-node>

The Resolve node is used to prefetch the data for a particular route before the component is loaded.

For example, consider an application where, in a page, some elements are displayed spontaneously, but other elements are loaded after observable is subscribed successfully which creates a delay in rendering on UI. In such a scenario Resolver allows applications to retrieve data first from an API response before the component gets loaded, allowing route navigation.

**How to Use**

1. On the Client services editor, Open an existing resolver service from the service list or click the** plus icon **to add a new Resolver Service.
2. Go to the Service > Drag and Drop the Resolver node to the canvas.
3. Drag and drop other nodes to define the resolver logic in the service flow.

****Node Properties**
**

**Name: **Unique name of the node which will be displayed on the canvas. The default value of the name is Resolve.

**Input Variables: **A list of read-only **bh.** variables in key value pairs generated by default by the node.

| **Key Element** | **Description** | **Value** |
| --- | --- | --- |
| bh.navigationRoute | Each page component in your app is associated with a route. This variable contains the information of the route associated with a page component loaded at a particular time | Value: ActivatedRouteSnapshot |
| bh.navigationRouteState | Contains the information of the state of router at a moment in time | Value: RouterStateSnapshot |

**Local Variables:** Use this field to initialize the local variables for the flow. Local variables are private to the flow and cannot be accessed outside the flow.
