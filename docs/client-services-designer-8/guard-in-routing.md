# Guard-In-Routing

<https://documentation.neutrinos.com/articles/#!client-services-designer-8/guard-in-routing>

The guard-In-Routing node is used to call canActivate method that returns value (a Boolean) to determine if the current user is allowed to activate a child of the route. Which means it determines whether an user is allowed to navigate to a specific page.

The guard-in-Routing node can be bonded with [script](/articles/client-services-designer-8/script-node) node where you can define the routing logic of a page.

**How to Use**

1. On the Client services editor, Open an existing Can-Activate service from the service list or click the** plus icon **to add a new Can-Activate Service.
2. Go to the Service > Drag and Drop the Guard-in-Routing node to the canvas.
3. Drag and drop other node to define the routing logic in the service flow

**Node Properties**

**Name: **Unique name of the node which will be displayed on the canvas. The default value of the name is Guard-in-Routing.

**Input Variables: **A list of read-only **bh.** variables in key value pairs generated by default by the node.

| **Key Element** | **Description** | **Value** |
| --- | --- | --- |
| bh.navigationRoute | Each page component in your app is associated with a route. This variable contains the information of the route associated with a page component loaded at a particular time | Value: ActivatedRouteSnapshot |
| bh.navigationRouteState | Contains the information of the state of router at a moment in time | Value: RouterStateSnapshot |

**Local Variables:** Use this field to initialize the local variables for the flow. Local variables are private to the flow and cannot be accessed outside the flow. Toggle the output button to use the variable as output variable.

To add a local variable:

1. Enter a local key
2. Choose the type of value to be associated with the key. You can select string, number, boolean, or null.
3. Enter a value to be associated with the key.
4. To set the variable as an output variable, toggle the Output button to true.
5. Click the + icon to add the variables.

Once created, these variables can be referred to as bh.input and bh.local variables, See [Properties](/smart/project-server-side-service-designer/properties-in-server-services) to learn more about these variables/flow objects.
