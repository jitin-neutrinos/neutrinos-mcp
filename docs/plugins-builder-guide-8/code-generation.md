# The BaseComponent Class

<https://documentation.neutrinos.com/articles/#!plugins-builder-guide-8/code-generation>

Use this editor to define the code generation of the node which will be executed in the service flow when you run the app.

Every service in service designer generates a class and the code generated by each of the nodes in that service corresponds to a member method of that service class. (A node can do a lot more than that, which we will be exploring further below, but this is the basic idea).

The communication between the nodes (methods) will happen through an object named **bh** which will be passed to each of the methods and returned by each of the methods. Between accepting and returning the **[bh object](/smart/project-service-designer-user-s-guide/system-defined-properties)**, the node will modify the properties of the object in its logic.

When you create a node, the default template code is generated with all the needed scaffolding. A class extending **BaseComponent** is defined. **BaseComponent** is the class that contains certain logic to register this node with the Neutrinos Studio for code generation. It also contains some overridable methods that can be utilized to generate the code.

### The BaseComponent Class

The BaseComponent class has several methods and static variables used by the code generation of Neutrinos Studio. You can override these methods to provide your own implementations.

This class is imported from the [bhive-toolkits](/smart/project-concepts/bhive-toolkits-package) package which contains the SDK to develop nodes.

```javascript
let BaseComponent = require('@jatahworx/bhive-toolkits').BaseComponent
```

The super call of BaseComponent takes the following arguments:

```javascript
super(constructorOptions.id, constructorOptions.name, "neutrinos_service_designer_<generated_node_name>", "
```

All the arguments are required. The third and fourth arguments are based on the **generated node name** for the node.

### Methods in the BaseComponent Class

The BaseComponent class has various methods that you can override with the same arguments and return types. These methods will be called during various Code Generation life cycles by Neutrinos studio. The overridable methods are:

#### generateImports(rootpaths)

This method should return an array of objects containing** libraries**, **modules**, or **an alias**. This generates the imports for the service file where the node is used. Here, you can import modules from and files and libraries. If the implementation of the generateImports is as below:

```javascript
/**   * returns Array of {   *  library: string,   *  modules: [string],   *  alias: string   * }   */  generateImports() {      return [          {              library: 'express-session',              alias: 'expressSession',          },          {              library: '../helper/generic/SessionStore',              modules: [                  'TypeormStore'              ]          },          {              library: 'typeorm',              modules: [                  'getConnection'              ]          }      ]  }
```

Then, the imports generated in the service file (where the node is used in a flow) will be :

```javascript
import * as expressSession from 'express-session';import { SessionStore } from '../helper/generic/SessionStore';import {getConnection} from 'typeorm';
```

#### generateSnippet (required) (serviceType (client | server), serviceClassTemplate)

This method is used to generate the logic of the service class method corresponding to the node. It describes the runtime logic of the node. This method should always return a string value or OptionsObject. If a string is returned, it should be the run-time logic of the node. This string is wrapped in a try/catch block which in turn is wrapped in a function.

OptionsObject - Used for nodes that generate more complex code, the generateSnippet method can return an object with these options which essentially makes every part of the wrapping code modular.

- nodeSnippet: String - a string that is to be wrapped.
- async(optional): Boolean - Whether the wrapping function is async. True by default.
- returnSnippet(optional): String - The expression that this node returns. Defaults to the [flow object(bh)](/smart/project-server-side-service-designer/properties-in-server-services).
- appendNextNodePlaceholder(optional): Boolean - whether to generate appendnew_next_functionName placeholder.
- argsSnippet(optional): String - The arguments accepted by the function generated.
- noWrap(optional): Boolean - Whether to wrap nodeSnippet or not.

Example of the generateSnippet method:

```javascript
generateSnippet(serviceType, serviceClassTemplate) {        /*Eg for node logic                                                             (confignode nodeName)        return `let configObj = this.sdService.getConfigObj('306d616b-3471-2452-0320-bdc8c7eae343', '${this.configId}')        let listUtil = new sftpUtil();        await listUtil.listUtilSftp(configObj,${this.remotePath},${this.pattern});        `;*/        return `            let configObj = this.sdService.getConfigObj('d62ae860-070b-eb80-8d36-33532fc17108', '${this.configId}');            let snsInst = new snsUtil();            snsInst.initialize(configObj)            ${this.result} = await snsInst.${this.operation}({                Name: ${this.constructorOptions.topicName},                Attributes:  ${this.constructorOptions.attributes},                Tags: ${this.constructorOptions.tags},                NextToken : ${this.constructorOptions.nextToken},                TopicArn : ${this.constructorOptions.topicArn},                AttributeName : ${this.constructorOptions.attributeName},                AttributeValue : ${this.constructorOptions.attributeValue}            });        `;
```

#### getListenerSnippet()

This method is used to register listeners in a service. If you are creating a start node - which is the starting point of a flow, you should use this method to generate the snippet in this method.

```javascript
getListenerSnippet(){  let listenerSnippet = this.constructorOptions.listenerType === 'on' ?                          `pubsubInstance.on` : `pubsubInstance.once` ;  return `${    listenerSnippet}  (${   this.constructorOptions.eventName}   , async data => this.${   this.constructorOptions.functionName}   (data))`;}
```

#### updateTemplate (optional) (serviceClassTemplate)

This callback gets the whole service file as a string. Manipulate anything that you want to update and return the file string back for code generation. This method is useful in changing the **constructor** options of the service class.

#### getErrorTemplate() (optional)

We use the [prettier](https://prettier.io/) library to validate the code snippet returned by **generateSnippet. **Given below is the default error template where the string returned from the generateSnippet method is appended at **//appendnew_node** placeholder comment and then validated by **prettier**.

If you wish to change the error template, implement the getErrorTemplate() function.

```javascript
getErrorTemplate() {        return `        export class errorCheck {                //appendnew_node        }        `;    }
```

#### getCallTemplate()(optional)

If the string returned from the **generateSnippet **method is a function, then implement this method to Inform Neutrinos Studio on what code should be generated to call the method generated by the node.

```javascript
getCallTemplate() {      return "bh = await this." + this.functionName + "(bh);"  }
```
