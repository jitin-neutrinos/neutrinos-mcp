## Services

Services are used to share data and communicate between components and external data sources. Using Neutrinos Studio, you can design two types of services:

### Client services

In application development, **client services** refer to everything in an app that is displayed or takes place on the client-side (end-user device). This includes what the user sees, such as text, images, and the rest of the User Interface, along with any actions that an application performs within the user's browser. Markup languages like HTML and CSS are interpreted by the browser on the client side. In addition, many contemporary developers are including client-side processes in their application architecture and moving away from doing everything on the server-side.

This is because, the problem with hosting all of the processes on the server-side is that each request involving one of them has to travel all the way from the client to the server, every time. This introduces a great deal of latency. For this reason, contemporary applications have started to run more code on the client side.

With the Neutrinos [Client Services Designer](/articles/concepts-publication/client-services-designer), you can configure such client-side services with ease by dragging and dropping service nodes and creating service flows in the Neutrinos Studio.

### Server services

**Server service** refers to the operations that are performed by the server in a client-server relationship. Operations are performed on the server to get access to information or functionality that is not available on the client, or because performing such operations on the client would be slow, unreliable, or insecure.

For example,  rendering dynamic webpages, interacting with databases, performing identity authentication, and sending push notifications.
