# Purpose

<https://documentation.neutrinos.com/articles/#!pulse-publication/change-tracking-pulse>

Change tracking is a system capability that records, manages, and exposes information about modifications made to data, configurations, or system artifacts over time. Change tracking enables the platform to capture what changed, when it changed, who made the change, and the previous and updated values.

## Purpose

The primary objectives of change tracking are:

- **Audit and compliance**: Provide a verifiable history of system changes.
- **Traceability**: Allow users and systems to trace data evolution over time.
- **Operational debugging**: Help identify the source of errors or unintended modifications.
- **Version awareness**: Support rollback, comparison, or historical analysis when applicable.

To view and access the change tracking in the Neutrinos Alpha Platform, follow the steps below:

1. In Workflow Studio, select the required project and navigate to its workspace.
    ![alpha-change-tracking-initial-project-page](/resources/Storage/pulse-publication/images/alpha-change-tracking-initial-project-page.png)
2. From the left navigation panel, select Branching within the project.
    ![alpha-change-tracking-navigation-panel-branching](/resources/Storage/pulse-publication/images/alpha-change-tracking-navigation-panel-branching.png)
3. On the Branching landing page, the interface displays commit information in a tabular format for all branches. By default, commits from All Branches are listed.
    ![alpha-change-tracking-landing-page](/resources/Storage/pulse-publication/images/alpha-change-tracking-landing-page.png)
  - **Commit ID**: Specifies an identifier generated by the version control system to uniquely reference a specific set of changes. This identifier enables precise operations such as checkout, revert, and cherry-pick.
  - **Commit Message**: A brief, human-readable description of the change that conveys its intent and scope. This description is essential for understanding the context without inspecting code diffs. Well-written commit messages improve long-term maintainability and traceability.
  - **Branches**: Indicates the branch or branches to which the commit belongs. This helps identify whether a change is part of the primary code line or a feature or development branch. It supports multi-branch workflows and release isolation.
  - **Author**: Displays the user who created the commit, establishing accountability and ownership of changes. This information is useful for collaboration, reviews, and follow-up discussions.
  - **Date and Time**: Shows when the commit was made, which is useful for timeline analysis, release audits, and correlating changes with incidents or deployments. This column can be sorted in ascending or descending order to view the latest changes first or the earliest changes first.
  - **Action**: This column contains a kebab icon, clicking which allows you to choose to view details of the commit of that particular row.
  - **Supporting Controls**:
    - **Search Bar**: Allows filtering commits by commit ID or message, aiding quick lookup.
    - **Branch Filter**: Enables viewing commits across all branches or a specific branch.
    - **Pagination & Row Count**: Supports navigation between pages and allows you to select the number of rows displayed per page.
