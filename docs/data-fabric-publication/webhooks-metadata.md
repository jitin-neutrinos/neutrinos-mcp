# Webhooks

<https://documentation.neutrinos.com/articles/#!data-fabric-publication/webhooks-metadata>

This section outlines the fields included in the Webhook sheet of the Excel workbook.

| **Fields** | **Description** | **Naming Convention** |
| --- | --- | --- |
| ObjectAPIName | The ObjectAPIName field in a Webhook specifies the target object with which the Webhook is associated. It establishes the binding between the Webhook and a specific object, ensuring that events or data changes related to that object are captured and transmitted to external systems. | Type: StringFormat:CamelCase or PascalCase with no spaces (e.g., Customer, OrderDetail, InvoiceRecord).Must start with an uppercase letter.Special characters (except underscores) are generally not allowed.Must match the API name of an object already defined |
| FieldAPIName | The FieldAPIName field in a Webhook specifies the exact field within the target object (defined by ObjectAPIName) that the Webhook monitors or reacts to. It refines the scope of the Webhook by ensuring it is triggered only when a specified field in the object changes or meets certain conditions. | Type: StringFormat:Typically camelCase or snake_case, depending on system standards.Should start with a lowercase letter.Multiple words should be concatenated in camelCase (e.g., orderStatus, customerEmail).Underscores (_) may be used for readability in snake_case (e.g., order_status, customer_email).Must be unique within the context of its parent object. |
| TargetURL | The TargetURL field specifies the endpoint address to which the Webhook sends HTTP requests when the configured event occurs. This is the destination system or service that will receive the event notification. | Type: String (must be a valid URI).Format:Should always start with the protocol: https:// (preferred) or http:// (not recommended for production).Must include a valid domain or IP address, and may include:Path (e.g., /events/orders)Query parameters (e.g., ?type=update) |
| ClientID_ENV | The ClientID_ENV field specifies the client identifier used by the Webhook to authenticate against the external system’s API. This identifier is usually tied to the integration’s application registration in the target system and may vary across environments (e.g., Development, Staging, Production). | Type: String (alphanumeric, case-sensitive). |
| ClientSecret_ENV | The ClientSecret_ENV field specifies the secret key associated with the client identifier (ClientID_ENV) that a Webhook uses to authenticate with an external system. It works in tandem with the Client ID to complete the authentication process, typically as part of an OAuth 2.0 client credentials flow or other secure integration method. | Type: String.Format:The value itself is usually system-generated |
| API_URL_ENV | The API_URL_ENV field specifies the base API endpoint of the external system to which the Webhook connects. It defines the environment-specific URL where authentication, event delivery, or additional API interactions will occur. | Type: String (must be a valid URI).Format:Should always start with a protocol: https://.Should reflect the environment explicitly (DEV, QA, STAGE, PROD). |
| API_METHOD_ENV | The API_METHOD_ENV field specifies the HTTP method that the Webhook should use when making requests to the external system’s API. It defines how the payload or interaction is performed against the target endpoint, and can vary across environments (e.g., Development, QA, Production). | Type: String (must be a valid HTTP method keyword). |
| Body_OnCreate | The Body_OnCreate field defines the payload structure that the Webhook sends to the target system when a new object instance is created. It allows admins to configure exactly what data fields, values, and formatting should be included in the HTTP request body at the time of object creation. | Type: String (structured as JSON/XML payload template). |
| Body_OnUpdate | The Body_OnUpdate field defines the payload structure that a Webhook sends to the external system whenever an existing object instance in Data Fabric is updated. This allows administrators to configure what information is included in the notification when changes occur, ensuring that downstream systems stay in sync. | Type: String (structured as JSON/XML payload template). |
| Body_OnDelete | The Body_OnDelete field defines the payload structure that a Webhook sends to an external system whenever an object instance is deleted. This ensures that downstream or integrated systems are notified about record removals and can take appropriate actions, such as cleaning up related data, updating statuses, or maintaining data consistency. | Type: String (structured as JSON/XML payload template). |
| Field_Body_OnUpdate | The Field_Body_OnUpdate defines the payload structure of a Webhook that is triggered when a specific field in an object is updated. Unlike the general Body_OnUpdate (which applies when any field changes), Field_Body_OnUpdate allows you to configure Webhook notifications at a field level, enabling finer-grained control over external system synchronization. | Type: String (structured as JSON/XML payload template). |
| Field_Body_OnNull | The Field_Body_OnNull defines the Webhook payload template that is triggered when a specific field in an object becomes null (empty or cleared). | Type: String (structured as JSON/XML payload template). |
| Schedule_Field | The Schedule_Field defines the field in the object that determines the schedule or timing for when a Webhook should be triggered. Unlike event-driven Webhooks (e.g., OnCreate, OnUpdate, OnDelete), the Schedule_Field is used for time-based or conditionally delayed Webhook executions. | Type: String (must reference a valid FieldAPIName of type Date or DateTime). |
| Schedule_Cron | The Schedule_Cron defines the cron expression that determines how often and when a Webhook should be executed. Unlike Schedule_Field (which is tied to an object’s date or datetime field), Schedule_Cron is independent of object data and uses time-based rules to trigger Webhooks at recurring intervals. This enables administrators and developers to configure Webhooks for recurring tasks, periodic synchronization, and automated notifications without relying on field updates. | Type: String (cron expression format). |
| Enabled | The Enabled field defines whether a Webhook is active and allowed to execute in Data Fabric. It functions as a simple toggle (on/off switch) that determines if the Webhook should listen to events, schedules, or triggers associated with it. | Type: Boolean (true / false). |
